# 디자인 의뢰 첨부파일 기능 — 구현 계획

> 작성: 2026-07-22 · 관련 Handoff: 이 문서 하단 체크리스트
> 요청: 디자인 의뢰 등록/수정 시 파일 첨부(pptx, pdf, mp4, html, txt, jpg/jpeg, png, zip 등),
> 파일당 25MB 이하, 의뢰당 최대 5개.

## 확정된 결정사항

1. **DB**: 별도 모델 `DesignRequestAttachment` (1:N, `onDelete: Cascade`)
2. **다운로드**: 기존 페이지와 동일한 **서버 프록시** 방식 + `requireAuth`
   - 미들웨어는 `/api/*`를 자동 보호하지 않음([middleware.ts:57-61](../middleware.ts#L57)) → 각 라우트가 직접 `requireAuth`.
   - 프록시(`Content-Disposition: attachment`)라 html 등도 브라우저에서 실행되지 않고 "저장"으로 처리됨.
3. **개수/용량**: 의뢰당 **최대 5개**, 파일당 **25MB**, 확장자 화이트리스트

## 재사용하는 기존 인프라

| 용도 | 위치 |
|---|---|
| S3/MinIO presigned 발급 | `lib/s3/post-storage.ts` `s3GetPresignedPostUpload`, `lib/b2.ts` `getPresignedUploadUrl` |
| 안전 파일명 | `lib/b2.ts` `generateSafeFileName` |
| 브라우저 직접 업로드 | `lib/presigned-client-upload.ts` `uploadWithPresignedEntry` |
| 프록시 다운로드 | `lib/b2.ts` `downloadFile` (참고: `app/api/notices/download/route.ts`) |
| S3 객체 삭제 | `lib/b2.ts` `deleteFileByUrl` |

## Storage 정책

- **신규 버킷 없음.** 기존 `posts` 버킷 재사용.
- 객체 키 prefix: `design-requests/{safeFileName}` (safeFileName에 timestamp+random 포함되어 충돌 없음).
- 공개 버킷이지만 다운로드는 프록시 라우트를 통해서만 UI에 노출(직접 URL은 화면에 노출하지 않음).

## 검증 규칙 (서버·클라 공유 — `lib/design-request-attachments.ts` 신설)

- 확장자 화이트리스트: `pptx, pdf, mp4, html, htm, txt, jpg, jpeg, png, zip`
- MIME 화이트리스트(가능 범위) + 확장자 병행 검사
- 파일당 최대 `25 * 1024 * 1024` bytes
- 의뢰당 최대 5개 (기존 + 신규 합산)

## 데이터 모델 (Prisma)

```prisma
model DesignRequestAttachment {
  id        String        @id @default(cuid())
  requestId String
  request   DesignRequest @relation(fields: [requestId], references: [id], onDelete: Cascade)
  fileName  String        // 원본 파일명(표시·다운로드명)
  fileUrl   String        // posts 버킷 객체 URL/키
  fileSize  Int           // bytes
  mimeType  String
  createdAt DateTime      @default(now())

  @@index([requestId])
  @@map("design_request_attachments")
}
```

`DesignRequest`에 back-relation 추가: `attachments DesignRequestAttachment[]`

마이그레이션: `prisma/migrations/2026XXXXXXXXXX_add_design_request_attachments/migration.sql`
(순수 additive — 데이터 보존, `migrate deploy` 전진 전용, shadow DB 미사용)
