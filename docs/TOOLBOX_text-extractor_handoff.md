## 2. 기능 명세

**레이아웃(이전 메뉴와 같은 틀)**: 페이지 헤더(`page-header-title` 「텍스트추출(OCR)」) + **좌측 작업 영역 + 우측 410px 패널**(xl 이상). **1280px 미만(P1 결정)**: Sheet를 쓰지 않고, 「텍스트 추출」 버튼을 헤더로·결과를 미리보기 아래 본문 카드로 옮긴다 — 결과를 보며 고치고 복사하는 게 주 작업이라 Sheet에 숨기면 불편하고, 설정 항목이 없어 Sheet에 넣을 것도 없다(파일명 일괄 변경 P5와 같은 판단). P0의 「인식 설정」 Sheet는 제거했다.

**작업 영역(좌)**
- 파일이 없을 때: 업로드 영역(클릭·끌어다 놓기·Ctrl/⌘+V 캡처 붙여넣기) + 「이렇게 사용하세요」 안내 + 「파일은 서버로 올라가지 않습니다」
- 파일이 있을 때: 원본 미리보기(이미지 / PDF 페이지 썸네일·페이지 이동) — P3에서 인식 상자 표시·영역 지정

**우측 패널(「텍스트 추출」)**
1. (PDF만) **페이지 범위**(시작 ~ 끝, 기본 1 ~ min(전체, 50), 「전체 N쪽」, 검증 안내) + **「모든 페이지를 OCR로 읽기」** 스위치(PDF 글자가 깨져 나올 때)
2. 인식 언어 표시(「한국어 + 영어」, 선택 없음 — D4) + **「텍스트 추출」** 버튼
3. **추출 결과** — 텍스트 영역(수정 가능) + 요약(PDF: 「3쪽 · PDF 글자 2쪽 · OCR 1쪽」)·글자 수 + 「전체 복사」·「.txt 저장」(파일명 `원본이름.txt`). PDF 여러 쪽은 `--- N쪽 ---` 구분선
4. 안내 — 결과를 꼭 확인할 것, 표는 행 단위 텍스트, 첫 사용 시 모델(약 18MB)을 한 번 내려받고 파일은 서버로 가지 않음

**진행 카드(작업 영역 가운데)**: ① 인식 모델 준비(첫 사용 시 MB·% 진행률) → ② 글자 영역 찾기 → ③ 글자 읽기(n / N줄) + 경과 시간 + 「취소」. PDF는 위에 「2 / 5쪽 (6쪽)」 + 페이지 진행 막대, 텍스트 레이어로 읽는 페이지는 단계 대신 「PDF에 들어 있는 글자를 읽는 중」

**미리보기**: 이미지는 그대로, PDF는 페이지를 그려 보여 주고 아래 가운데 「◀ 3 / 12쪽 ▶」로 넘긴다. 새 파일·페이지를 그리는 동안은 이전 그림을 지우고 스피너. 오른쪽 위 도구: 「영역 선택」(누름 상태) · 「선택 해제」(영역이 있을 때) · 「인식 영역 표시/숨기기」(추출 후) · 「새 파일 열기」

**영역 지정·인식 상자(P3)**: 「영역 선택」 → 드래그(마우스·터치)로 사각형 → 선택 모드 자동 종료, 바깥은 어둡게·점선 테두리. 「추출 범위: 선택 영역」(패널·본문 카드)·「선택 해제」·Esc. PDF는 **보고 있는 페이지의 영역만**(페이지 범위 입력 잠금·안내), 페이지를 넘기면 해제. 추출 후 읽은 줄을 노란 상자로 겹쳐 보이고, 마우스를 올리면 읽은 글자(SVG title)

## 3. 구조

- 로직 `lib/toolbox/text-extractor/`
  - `ocr.ts`(순수): 감지 입력 크기·텐서, 확률 맵 → 상자(연결 성분·넓히기), 인식 입력 폭·텐서, 사전, CTC 디코딩
  - `layout.ts`(순수): 상자 → 읽는 순서의 줄 텍스트(XY-cut 변형 — 다단은 왼쪽 단부터, 표·영수증은 행 단위)
  - `text.ts`(순수): 한글 사이 마침표·쉼표 뒤 띄어쓰기 보정, 글자 수, `.txt` 파일명
  - `model.ts`: 모델 3개(감지·인식·사전) 내려받기 — 진행률 합산·SHA-256 확인·Cache Storage(`toolbox-ocr-model-v1`)
  - `protocol.ts` · `ocr.worker.ts`(onnxruntime-web WASM 단일 스레드, OffscreenCanvas로 축소·자르기) · `engine.ts`(`OcrEngine` — 내려받기·Worker 준비·추출·취소, 모자이크 `DetectionEngine`과 같은 구조)
  - `text-extractor.test.ts`
  - `pdf.ts`(순수): PDF 판별·크기(50MB)·페이지 범위(최대 50쪽) 검증, 텍스트 레이어 사용 판단(공백 제외 20자 이상), 텍스트 항목 → 화면 좌표 상자(뷰포트 행렬)·같은 줄 조각 합치기(`mergeLineFragments`), 렌더 배율, 페이지 합치기·요약
  - `pdf-document.ts`(브라우저): pdf.js 불러오기·PDF 열기(암호·손상 안내)·페이지 텍스트 읽기·페이지 그리기
  - **pdf.js는 webpack을 거치지 않는다** — `public/js/pdfjs/pdf.min.mjs`를 `import(/* webpackIgnore: true */)`로 브라우저가 직접 불러온다. Next 14 webpack이 pdfjs-dist 5의 `pdf.mjs`를 다시 번들링하면 `Object.defineProperty called on non-object`로 실패했다(react-pdf 경유도 같음 — 앱의 `PdfPreview`(react-pdf)는 현재 어디서도 쓰지 않아 기존 PDF Extractor에는 영향 없음). 워커 `public/js/pdf.worker.min.mjs`(기존)·디코더 wasm·cmaps·standard_fonts도 `public/js/pdfjs/`(README) — **pdfjs-dist(react-pdf가 설치) 5.4.296과 같은 버전·같은 파일인지 vitest가 확인**한다. react-pdf를 올리거나 지우면 이 테스트가 깨지므로 public 파일을 다시 복사한다
- 공용 재사용: `lib/toolbox/common/load.ts`(검증·EXIF 디코딩·클립보드 이미지), `export.ts`(`sanitizeFileName`·`downloadBlob`), `ort.ts`(PaddleOCR 선택 시), `components/toolbox/common/ImageUploadZone`(PDF도 받도록 문구·형식 확장 여부 검토)
