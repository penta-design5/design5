## 0. 운영/개발 워크플로우 (전제)
- 이 프로젝트(Layerary, Next.js 14 + Prisma + PostgreSQL + MinIO)는 **사내망에 배포되어 운영 중**이며 `design6.pentasecurity.com`에서 서비스됨.
- 개발 방식: **로컬에서 수정 → 변경 파일을 사내 서버에 반영 → `deploy/rocky`에서 앱 재빌드 → design6에서 검증.**

- ⚠️ **로컬에서 운영 DB/MinIO에 쓰기 테스트 금지**: 로컬 `.env.local`의 `S3_PUBLIC_BASE_URL=http://127.0.0.1:19000/edms`(localhost + edms 버킷) 때문에 업로드한 이미지 URL이 깨지고, 운영 DB도 오염됨. **쓰기/업로드 검증은 반드시 design6에서.** (이 세션에서 테스트32 게시물에 깨진 URL 2개가 운영 DB에 남은 사례 발생 — design6에서 해당 이미지 삭제 후 재업로드로 정리 필요.)

### C. HW 하드웨어 제품 갤러리 (핵심)
요구사항: 관리자가 제품 사진 업로드, 사용자가 보고 다운로드. 사이드바 **ICON과 캐릭터 사이**에 "HW". 목록은 바탕화면 카드와 동일, 카드 클릭 시 상세 이동. **편집/속성저장 없음** — 큰 미리보기 + 우측 제목·설명 + 다운로드만. **제품당 이미지 1장**, 관리자 수정+삭제 지원.

설계: 바탕화면(Desktop) 패턴을 본뜨되 **단일 이미지 전용 경량 모델**로 분리. 카드 UI는 Desktop, 상세 레이아웃은 Gallery 상세 참고.

## 3. Prisma 마이그레이션 주의 (중요)
- 이 프로젝트의 로컬 `prisma/migrations/`는 **baseline 1개로 압축**돼 있으나, 운영 DB `_prisma_migrations`에는 baseline 포함 **8개 과거 이력**이 기록돼 있음.
- 따라서 **`prisma migrate dev` 쓰지 말 것** — 드리프트로 인식해 "DB 리셋(전체 데이터 삭제)"을 요구함. (이 세션에서 실제로 리셋 프롬프트가 떠서 `N`으로 취소함.)
- 새 마이그레이션은 **파일을 직접 만들고 `npx prisma migrate deploy`로 적용**한다. deploy는 DB에 없는 마이그레이션만 적용하고 리셋하지 않음.
- C의 `20260608120000_add_hardware_products`는 이 방식으로 **노트북 터널 → 운영 DB에 이미 적용 완료**.

## 4. 배포 상태 & 남은 작업
- **DB(운영)**: `migrate deploy`(hardware_products 생성) + `db:seed`(HW 카테고리 추가, Character 이름 반영) **이미 적용됨**(노트북 터널). 서버에서 재실행 불필요.
- ⚠️ 그 결과 **현재 라이브 design6에 HW 메뉴와 Character 이름이 이미 노출됨.** 단 앱은 구버전이라 HW 클릭 시 "구현되지 않았습니다" 플레이스홀더가 뜸. → **빨리 앱을 재빌드해 정상화 필요.**
- **남은 작업**: 이번 세션의 모든 변경 소스 파일을 사내 서버에 반영 후 **앱 재빌드만** 하면 됨.

### 재빌드 명령
```bash
# /data/webapps/design5/deploy/rocky
docker compose -f docker-compose.yml -f docker-compose.app.yml --env-file .env up -d --build app
```
- 빌드 명령만으로는 마이그레이션/시드가 실행되지 않음(Dockerfile은 `prisma generate` + `next build`만 수행). 이번엔 DB가 이미 반영됐으므로 빌드만으로 충분.
- `--env-file`은 `.env`(Postgres/MinIO·빌드 인자 정의처)를 사용. `.env.app`은 앱 런타임용으로 compose의 `env_file`로 이미 주입됨.

  - `app/_category-pages/hardware/HardwareListPage.tsx` — 필터 탭(`HorizontalScrollEdgeFades`) + 필터별 재조회

- ⚠️ **데이터 함정(해결됨)**: `type` 컬럼 추가 전·구버전 POST로 만든 기존 제품은 `type=NULL` → 특정 필터에서 안 보임. 각 제품을 "수정"으로 열어 타입 지정·저장해 정리 완료. 신규 추가분은 자동 저장.
