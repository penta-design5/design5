## Context (배경)

SOURCE / TEMPLATE / BROCHURE 카테고리의 메뉴 페이지에서 게시물이 **추가 또는 수정**될 때, 그 메뉴를 구독한 사용자에게 **이메일로 알림**을 보내는 기능이다. 사용자는 각 메뉴 페이지에서 직접 구독/취소할 수 있고, 관리자는 대시보드에서 이 기능 전체를 켜고 끌 수 있다.

기존 인프라를 최대한 재사용한다:
- 이메일: `lib/mail/design-request-notification.ts` (nodemailer + `getMailTransporter`, 수신자 조회 → 메일 작성/발송, 오류 삼킴) 패턴을 그대로 복제.
- 전역 토글: `AppSettings` 단일행 모델 + `lib/app-settings.ts` get/set + `app/api/app-settings/credentials-login/route.ts`(GET/PATCH) 패턴.
- UI: `components/ui`의 `Button`, `Tooltip`, `Dialog`, `Switch`, `Badge`, `DropdownMenu` 등 shadcn 컴포넌트.

### 확정된 범위 결정
- 구독 단위: **메뉴(카테고리)별**. 구독 버튼은 각 메뉴 페이지마다 배치.
- 구독 시 같은 버튼이 **"구독 취소"로 토글**된다. → (당초 요청했던) *사용자 설정 화면의 별도 "구독 취소" 섹션은 구현하지 않음*.
- **제외 메뉴**: `다이어그램`(slug `diagram`), `eDM`(slug `edm`) — 둘 다 사이드바에 숨겨져 있음. 구독 대상 = 사이드바에 노출되는 SOURCE/TEMPLATE/BROCHURE 메뉴만.
- 알림 아이콘(요구사항 #4, 헤더 벨+뱃지+드롭다운+읽음처리)은 **별도 2단계(Phase 2)**로 분리. 본 계획에서는 설계 개요만 두고, Phase 1(구독/취소 토글 + 관리자 스위치 + 메일 발송)을 먼저 완성한다.

## Phase 1 — 구독/취소 토글 + 관리자 전역 스위치 + 메일 발송

### 1. 데이터 모델 (`prisma/schema.prisma`)

**MenuSubscription 모델 신규 추가** — 사용자×카테고리 구독 관계.
```prisma
model MenuSubscription {
  id         String   @id @default(cuid())
  userId     String
  categoryId String
  createdAt  DateTime @default(now())

  user     User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  category Category @relation(fields: [categoryId], references: [id], onDelete: Cascade)

  @@unique([userId, categoryId])
  @@index([categoryId])
  @@map("menu_subscriptions")
}
```
- `User` 모델에 `menuSubscriptions MenuSubscription[]` 관계 추가 (line 39~62 영역).
- `Category` 모델에 `subscriptions MenuSubscription[]` 관계 추가 (line 65~83 영역).

**AppSettings에 전역 토글 필드 추가** (line 316~322):
```prisma
model AppSettings {
  id                       String   @id @default("default")
  showCredentialsLogin     Boolean  @default(true)
  menuSubscriptionEnabled  Boolean  @default(true)   // ← 추가
  updatedAt                DateTime @updatedAt
  @@map("app_settings")
}
```

> **마이그레이션 주의**: DB는 내부 개발 서버(design6, 외부 접근 불가)에 있다. `npx prisma migrate dev --name menu_subscription`는 개발 서버 DB에 접근 가능한 환경에서 실행해야 한다. 로컬/CI 테스트는 DB 비의존으로 작성.

### 2. 전역 토글 헬퍼/엔드포인트 (`lib/app-settings.ts` 확장)

`lib/app-settings.ts`에 `getMenuSubscriptionEnabled()` / `setMenuSubscriptionEnabled(value)` 추가 (기존 `getShowCredentialsLogin`/`setShowCredentialsLogin`의 upsert 패턴 그대로).

신규 라우트 `app/api/app-settings/menu-subscription/route.ts` (GET/PATCH):

- 권장: **공개 조회는 `app/api/app-settings/public/route.ts`에 `menuSubscriptionEnabled` 필드를 추가**해 구독 버튼이 단일 fetch로 전역 상태를 알 수 있게 함. PATCH(관리자 변경)는 신규 `menu-subscription/route.ts`에 둔다.

### 3. 구독 API (`app/api/subscriptions/...`)

`withRouteHandler` + `requireAuth()` + `zod` 패턴 사용.

- `app/api/subscriptions/route.ts`
  - `GET`: 현재 사용자가 구독 중인 categoryId 목록 반환 `{ categoryIds: string[] }` (페이지 버튼 초기 상태용; 또는 아래 status 방식).
  - `POST` `{ categoryId }`: 전역 토글 OFF면 거부. `menuSubscription.upsert`로 구독 생성(중복 무시). 대상 카테고리가 구독 대상(SOURCE/TEMPLATE/BROCHURE, slug ∉ {diagram, edm})인지 검증.
  - `DELETE` `{ categoryId }`: 해당 구독 삭제(`deleteMany`).
- 검증 헬퍼: `lib/categories.ts`의 `getCategoryBySlug`/카테고리 조회로 type·slug 확인.

### 5. 메일 알림 헬퍼 (`lib/mail/menu-subscription-notification.ts` 신규)

`design-request-notification.ts`를 복제해 작성. 시그니처 예:
```ts
export async function notifyMenuUpdate(input: {
  categoryId: string
  action: 'created' | 'updated'
  title: string
  slug: string        // 메뉴 페이지 링크용
  postId?: string     // Post 기반이면 상세 링크
}): Promise<void>
```
동작:
1. `getMenuSubscriptionEnabled()`가 false면 즉시 return.
2. `getMailTransporter()` 없으면 경고 로그 후 return.
3. `prisma.menuSubscription.findMany({ where: { categoryId }, include: { user: { select: { email } } } })`로 수신자 조회. 이메일 소문자 dedupe.
4. 카테고리명 조회(`prisma.category`), 제목/본문 작성:
   - 제목: `[${BRAND_EN}] {카테고리명} 업데이트` (제목은 `formatTitleForEmailSubject` 재사용, 길이 제한).
   - 링크: `getSiteOrigin()` + `/${slug}` (Post면 `/${slug}/${postId}`).
   - text/html은 design-request의 escape/footer 패턴 재사용.
5. `Promise.all`로 각 수신자 발송, 개별 오류는 로그만. 전체 try/catch로 삼킴(응답 영향 없음).
6. **호출부에서 `await`** (서버리스 조기 종료 방지) — design-request와 동일.

`getSiteOrigin`/`escapeHtml`/`formatTitleForEmailSubject`는 design-request 파일에 private이므로, **공용 모듈 `lib/mail/utils.ts`로 추출 후 양쪽에서 import**(권장) 또는 새 파일에 복제.

### 6. 알림 발송 훅 삽입 (생성/수정 라우트)

각 라우트에서 DB 생성/수정 성공 직후 `await notifyMenuUpdate(...)` 호출. 전역 OFF 및 수신자 0명은 헬퍼 내부에서 처리.

**(a) Post 기반 메뉴 — categoryId 보유, 한 곳씩만 수정**
- `app/api/posts/route.ts` `POST` (생성 직후, line ~284 `prisma.post.create` 결과 사용):
  `notifyMenuUpdate({ categoryId: post.categoryId, action:'created', title: post.title, slug: post.category.slug, postId: post.id })`
- `app/api/posts/[id]/route.ts` `PUT` (수정 직후, line ~316): `action:'updated'`. 수정 결과에 `category.slug` include 필요(없으면 include 추가).
- 이 한 쌍으로 CI/BI, ICON, Character, PPT, WAPPLES, D.AMO, iSIGN, Cloudbric **전부 커버**.

**(b) 독립 모델 메뉴 — categoryId 없음, pageType로 카테고리 역매핑**
각 라우트에서 고정 pageType으로 카테고리를 조회해 categoryId·slug를 얻은 뒤 호출.
- `app/api/hardware/route.ts` POST / `app/api/hardware/[id]/route.ts` PUT → pageType `hardware`
- `app/api/desktop-wallpapers/route.ts` POST / `[id]` PUT → pageType `desktop`
- `app/api/welcomeboard-templates/route.ts` POST / `[id]` PUT → pageType `welcomeboard`
- `app/api/card-templates/route.ts` POST / `[id]` PUT → pageType `card`
- 카테고리 조회: `prisma.category.findFirst({ where: { pageType }, select: { id:true, slug:true } })`. 작은 헬퍼 `resolveCategoryByPageType(pageType)`를 `lib/categories.ts`에 추가해 재사용.
- 독립 모델은 항목 상세 페이지 URL이 명확하지 않으므로 **메일 링크는 메뉴 페이지(`/${slug}`)로** 통일(안전).

**(c) diagram, edm 라우트(`app/api/diagrams`, `app/api/edm`)에는 훅을 넣지 않음.**

### 7. 관리자 전역 스위치 UI (대시보드)

`app/(dashboard)/admin/dashboard/page.tsx`(현재 통계 전용, `'use client'`)에 **"메뉴 구독 알림" 토글 카드** 추가:

## Phase 2 — (검토) 업데이트 알림 아이콘 [별도 단계, 설계 개요만]

> 본 계획에서는 구현하지 않음. 읽음 상태 추적이 필요해 작업량이 큼. 아래는 향후 설계 메모.

- **모델**: `UpdateLog { id, categoryId, postId?, title, action, createdAt }` — `notifyMenuUpdate` 호출 시점에 함께 기록. 사용자별 읽음 상태는 `NotificationRead { userId, updateLogId @@unique }` 조인 테이블.
- **뱃지 수**: 현재 사용자가 구독한 카테고리의 `UpdateLog` 중 `NotificationRead`에 없는 건수.
- **UI**: `components/category-pages/layout/Header.tsx` 검색 폼(line 169) **좌측**에 `Button(variant=ghost,size=icon)` + 벨 아이콘(lucide `Bell`) + 우상단 `Badge`(count). 클릭 시 `DropdownMenu`/`Popover`로 목록 드롭다운, 아이템 클릭 → 해당 게시물 이동 + `NotificationRead` 생성(회색 처리 + 뱃지 차감).
- **API**: `GET /api/notifications`(목록+미읽음수), `POST /api/notifications/[id]/read`.

## 검증 (Verification)

1. **마이그레이션/타입**: 개발 서버 DB 접근 환경에서 `npx prisma migrate dev --name menu_subscription` → `npm run db:generate` → `npm run typecheck`.
2. **구독 토글**: 일반 사용자로 한 메뉴 페이지 접속 → `구독` 버튼 hover 시 툴팁 확인 → 클릭 → 다이얼로그 안내 + 버튼이 `구독 취소`로 전환 → 새로고침 후에도 `구독 취소` 유지 → 클릭 시 toast + `구독` 복귀.
3. **메일 발송**: 위 사용자로 구독 후, 관리자로 같은 메뉴에 게시물 추가/수정 → 구독자 메일함에 `[BRAND] {메뉴명} 업데이트` 수신 및 링크 확인. (`GMAIL_USER`/`GMAIL_APP_PASSWORD` 설정 필요; 미설정 시 콘솔 경고 후 스킵되는지 확인.)
4. **독립 모델 메뉴**: 바탕화면/웰컴보드/카드/HW 각 1건씩 추가 → 해당 메뉴 구독자에게 메일 가는지 확인(링크가 `/${slug}` 인지).
5. **전역 스위치**: 관리자 대시보드에서 토글 OFF → 모든 메뉴에서 구독 버튼 비노출, 게시물 추가해도 메일 미발송 확인 → ON 복귀 시 정상.
6. **제외 메뉴**: `다이어그램`/`eDM` 페이지(접근 가능한 경로)에 구독 버튼이 없고, 해당 콘텐츠 추가 시 메일이 가지 않는지 확인.
7. **회귀**: `npm run test`, `npm run lint`.
